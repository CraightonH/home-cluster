Renovate PRs #54 and #55 propose jumping directly to Talos v1.12.3 and k8s v1.35.0 respectively. **Neither PR can be merged as-is:**
- Talos does not support skipping minor versions (must go 1.9 -> 1.10 -> 1.11 -> 1.12)

**Urgency:** k8s 1.32 EOL is **Feb 28, 2026**. ~~CNPG 1.27.x EOL is March 9, 2026~~ -- already on operator 1.28.1 via chart 0.27.1.

## Phase 1 -- Talos v1.9.6 -> v1.10.9

### Breaking changes to watch
- **iSCSI IQN format changed.** Talos v1.10 generates deterministic IQNs from node identity. Your democratic-csi iSCSI setup with Synology NAS will break if the target ACLs only allow old IQNs. **Before upgrading the first node:** record current IQNs. **After each node:** check new IQN with `talosctl get iscsiinitiatorname`, update Synology target ACLs.
- **`.machine.install.extensions` ignored.** No impact -- already using boot assets/schematics.
- **cgroups v1 dropped.** No impact -- cgroups v2 is default since Talos v1.5.
- **Unified `/usr` filesystem.** Transparent for official extensions.
- **containerd config:** Your `containerd.yaml` patch uses `plugins."io.containerd.grpc.v1.cri"` which is the containerd 1.x CRI path. Talos should handle translation but verify CRI config still applies post-upgrade.

### Execution

```bash

# Workers first
talosctl --nodes 192.168.1.245 upgrade \
  --image factory.talos.dev/installer/f8a903f101ce10f686476024898734bb6b36353cc4d41f348514db9004ec0a9d:v1.10.9 \
  --wait=true --timeout=10m --preserve=true --stage   # node5 RPi

talosctl --nodes 192.168.1.243 upgrade \
  --image factory.talos.dev/installer/48369893e1b56c3e2c53575db56df55a90e260135591a0456b128e3459151c7a:v1.10.9 \

# Control planes (one at a time)
talosctl --nodes 192.168.1.242 upgrade \
  --image factory.talos.dev/installer/48369893e1b56c3e2c53575db56df55a90e260135591a0456b128e3459151c7a:v1.10.9 \
```

## Phase 3 -- Talos v1.11.6 -> v1.12.3

### Breaking changes to watch
- **Kexec hangs reported.** Use `--reboot-mode powercycle` for ALL nodes (not just RPi). Multiple users reported nodes becoming unavailable during v1.11->v1.12 with default kexec.
- **`.machine.network` deprecated.** Your talhelper generates `.machine.network.interfaces` via `networkInterfaces`. Still functional, but deprecated in favor of multi-document config (`LinkConfig`, `DHCPv4Config`, etc.). No immediate action needed.
- **etcd image source changed** from `gcr.io/etcd-development/etcd` to `registry.k8s.io/etcd`. Ensure nodes can pull from `registry.k8s.io`.
- **Feature flags locked:** `machine.features.rbac` locked to `true`, `cluster.apiServer.disablePodSecurityPolicy` locked to `true`. Your `disable-admission-controller.yaml` patch removes the entire `admissionControl` block (not PodSecurityPolicy specifically), so no conflict.
- **API server TLS cipher suites tightened** (CIS 1.12 benchmark). Could affect older clients; unlikely to be an issue.

### Execution

**Note: `--reboot-mode=powercycle` for amd64 nodes too (kexec hang workaround).**
